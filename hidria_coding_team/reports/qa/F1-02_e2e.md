### Diseño seguro (sin backend real)

- `webServer` compila `app/` con `VITE_SUPABASE_URL=https://test.invalid` y una **anon key
  sintética** (JWT `role: anon`); el guard build-time de `vite.config.ts` la acepta.
- La sesión se siembra en `localStorage` (`sb-test-auth-token`) con JWT de claims; el cliente
  sólo decodifica el payload (no verifica firma, la autoridad es RLS/EF).
- Las peticiones a `test.invalid` se **abortan**; `/auth/v1/**` se responden para que
  `signOut()` resuelva. No se llama a Supabase real.
- No hay contraseñas, Admin API ni seed con password: se cumple “sin secretos” y se evita
  depender de E3/E2.
